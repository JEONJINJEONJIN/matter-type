# 사물로 쓰다 — 버려진 것들도 모이면 말이 된다

쓸모없어진 물건들이 모여 입체 글자를 이루는 3D 오브젝트 타이포그래피 도구입니다. 멀리서는 문장, 가까이서는 버려진 물건 더미로 보이는 것을 목표로 합니다. Vite + TypeScript + three.js, 순수 HTML/CSS. 서버·CDN·외부 모델 없이 브라우저에서 작동합니다.

## 실행

Windows에서 **`START.cmd`를 더블클릭**하면 개발 서버와 브라우저가 열립니다. 실행 창은 사용 중 켜두세요. Node.js LTS가 필요하며, 처음 실행할 때 의존성이 없으면 자동 설치합니다.

```sh
npm install
npm run dev
npm run typecheck
npm test
npm run build
```

## 사용

텍스트를 입력하면 300ms 뒤 배치가 갱신됩니다. 최대 240자, 자동 줄바꿈·글자 단위 캐시를 지원합니다. 소재 팔레트에서 한 카테고리만 선택하거나 여러 카테고리를 섞고, 개별 물체 등장 비율을 조절합니다. 카메라 회전·줌, 글자 더블클릭 확대, 떼어내기, 시드·다시 섞기, 배열 모드, 바닥·조명·후처리, 이미지 부풀리기·GLB 업로드, 현재 시점의 2배 PNG 저장은 유지했습니다.

## 결정 사항

1. **글자의 뼈대는 절대 렌더링하지 않습니다.** SDF는 위치·크기 계산만 수행합니다. 글자 코어·텍스트 메시·와이어프레임·숨겨진 picking 몸체·코어 UI가 없습니다. 실제 물체 삼각형으로 선택합니다. 향후 기능 변경에도 이 원칙을 유지하며 회귀 테스트로 검사합니다.
2. 요청한 폐기물 **25종**을 기본 라이브러리로 제공합니다. 기존 구겨진 종이·반지·돌멩이의 형태는 유지했고, 전체 팔레트를 폐기물 컨셉으로 교체했습니다. 이전 팝아트 형태 생성 코드는 재사용 가능한 도우미와 과거 모델 소스로 남아 있지만 현재 선택 목록에는 나오지 않습니다.
3. `objects/library.ts`의 정의 하나가 id·이름·카테고리·factory·GLB 경로·재질·크기 범위·무게를 관리합니다. 정의의 `weight: light | medium | heavy`는 런타임 `massClass`로 전달하며, 기존 숫자 `weight`는 등장 비율입니다. 현재 낙하에는 질량별 물리 차이를 적용하지 않습니다.
4. `sizeRange`는 바운딩 구 반지름의 선호 범위입니다. 범위를 벗어나면 선택 확률을 낮추되 SDF 경계·속공간 보존을 우선합니다. 기본값은 `.06–.65`. 크기·회전·색은 기존 시드 기반으로 다르게 배정합니다.
5. 캔의 찌그러짐, 봉지·종이의 구김과 찢어진 테두리, 빗의 빠진 이, 머그 조각의 깨진 단면을 지오메트리로 표현합니다. 얼룩과 산화 반점은 정점 속성에 한 번 기록합니다. 매 프레임 형태를 다시 만들지 않습니다.
6. 기본은 채도 낮은 카테고리 색, 거친 표준 재질입니다. 캔·페트병만 약한 광택을 허용하고 금속은 높은 거칠기와 갈색 산화 반점을 사용합니다. 기존 재질 팩토리·인스턴싱 구조를 유지하고 기본 재질만 바꿨습니다. `library.standardShading=false`면 기존 툰 경로를 사용할 수 있습니다. 외곽선은 선택 기능으로 유지하되 기본 OFF입니다.
7. 뼈대 없이도 획을 더 채우도록 기본 후보 탐색 밀도를 1에서 **1.3**으로 올렸습니다. SDF 안쪽에 바운딩 구가 완전히 들어가는 조건과 기준 반지름의 공간 해시 검사는 유지합니다. 이후 보이는 물체는 겹침을 허용해 확대합니다. 철사·테이프만 고르면 빈 공간이 커 보일 수 있어 기본 조합에는 캔·병·종이·박스·건전지를 함께 넣습니다.
8. 물체마다 본체 InstancedMesh 한 개(+선택적 외곽선 한 개), 총량 12,000개, 글자 캐시·Worker 배치 계산을 유지합니다. 인스턴스 버퍼는 64개부터 필요량에 맞춰 늘어납니다. 가만히 있는 장면은 불필요하게 계속 렌더링하지 않습니다.

## 구조와 교체 방법

- `src/objects/library.ts`: 폐기물 25종 정의·재질·GLB 교체
- `src/objects/wasteForms.ts`: 파손·구김·마모 정점 속성을 포함한 절차 형태
- `src/objects/forms.ts`, `popForms.ts`: 기존 형태·도우미 재사용
- `src/render/toon.ts`: 표준/툰 재질 경로와 정점 얼룩·녹 표현
- `src/render/pieces.ts`: 종류별 인스턴싱·색·그림자·버퍼
- `src/config.ts`: 밀도·색·재질·찌그러짐·구김·산화·광택 설정
- `src/sampler.ts`, `textLayout.ts`, `sdfPlacement.ts`: 계산 전용 SDF·글자 캐시·시드 배치
- `src/ui.ts`: 기존 조작을 유지한 폐기물 카테고리와 컨셉 문구

`public/objects/can.glb`를 넣고 캔 정의에 `glbPath: '/objects/can.glb'`를 추가하면 시작할 때 교체합니다. 자기 완결적인 정적 GLB, 25MB/480삼각형 이하, 앞면 로컬 +Y 기준입니다. 스킨·모프·외부 파일 참조·텍스처 재현은 지원하지 않습니다. 오류가 나면 절차 형태를 유지하고 메시지를 표시합니다. 물체의 고유 메타데이터는 그대로 유지합니다.

## 검증

- Node 테스트 14개: 예산·시드·구멍·표면 선택·떼어내기·메타데이터·마모 속성·코어 경로 부재.
- 실제 브라우저 검사 62개: SDF 경계/구멍, Worker 시드 일치, 업로드·GLB 경로 대체, 카테고리 단독/혼합, 기능 OFF, 실제 물체 raycast.
- 25종 모두 48–360삼각형. 단일 지오메트리·단일 재질로 병합합니다.
- 성능은 `/tests/performance.html`에서 25종을 모두 선택한 30/60/120자로 검사합니다. CPU 배치 시간과 회전/재부착 FPS를 분리합니다.

기존 `docs/pop-*` 자료는 이전 팝아트 버전 기록입니다. 이번 컨셉의 검증 자료와 혼동하지 마세요. 일반 노트북의 60fps를 보장하는 측정은 아니며 GPU·브라우저·해상도에 따라 달라집니다.

### 장문 실측 — 2026-10-01

앱 내 브라우저, NVIDIA RTX 4080 SUPER / ANGLE D3D11, 960×540, DPR 1. 폐기물 25종 모두 같은 비율로 선택, 물체 12,000개, 그림자 ON(이동 중 갱신 20Hz), 코어 없음, 외곽선 OFF, 후처리 OFF. 회전/재부착을 각각 6초 측정했습니다.

| 글자 수 | 물체 수 | 배치 준비 | 회전 FPS | 재부착 FPS | 회전 GPU |
| ------- | ------: | --------: | -------: | ---------: | -------: |
| 30      |  12,000 |    239 ms |    164.9 |      158.9 |  0.90 ms |
| 60      |  12,000 |    161 ms |    164.9 |      159.8 |  1.45 ms |
| 120     |  12,000 |    206 ms |    164.9 |      159.6 |  1.37 ms |

모든 구간에서 250ms 이상 지연 0회, p95 프레임 간격 6.1–6.2ms였습니다. 이 환경에서는 60fps 목표를 충족했습니다. 배치 준비 시간은 이미 로드한 폰트와 재사용 캐시를 포함하는 테스트 조건이며, 신규 글자가 많은 첫 로딩 시간과 동일하지 않습니다. 매 프레임 배치 계산은 없습니다. 원자료는 `docs/waste-performance-results.json`, 기능 검사 기록은 `docs/waste-browser-checks.txt`입니다.

### 부피 보강

내장 폐기물의 짧은 축을 더 두툼하게 만드는 `library.bulk=0.5`를 추가했습니다. 최장 축에 비해 짧을수록 더 확장하고 기존 바운딩 구 안으로 정규화하므로 배치 규칙·글자 경계 제한을 유지합니다. `0`이면 이전 형태로 돌아갑니다. 색·물체 수·폴리곤 수는 바꾸지 않으며, 업로드 및 GLB 교체 모델은 원본 비율을 유지합니다. 타입 체크·빌드·14개 회귀 테스트 통과.


### 빈 공간을 메우는 전체 크기 2배 확대

`pop.coverageScale=2`로 덕지덕지·깊게 쌓기의 물체 전체 크기를 확대했습니다. 배치 중심·물체 수·색·폴리곤 수는 유지하고, 물체 사이의 겹침을 허용하여 틈을 메웁니다. 최종 크기는 글자 SDF 경계와 앞뒤 두께 범위로 제한하므로 가장자리에서는 2배보다 작을 수 있습니다. 드문드문은 기존 1배입니다. `library.bulk`는 물체 비율을 두툼하게 하는 별도 값입니다. 이전 장문 FPS 표는 이 확대 이전 측정이며 확대 후 FPS를 뜻하지 않습니다.

## 인터넷 공개 배포

GitHub Pages를 사용합니다. 공개 저장소 `JEONJINJEONJIN/matter-type`의 `main`에 변경을 push하면 `.github/workflows/deploy.yml`이 타입 체크·테스트·빌드 후 `dist`만 배포합니다. 별도의 서버나 유료 도메인은 필요하지 않습니다. Vite의 상대 경로 `base: './'` 설정으로 저장소 하위 주소에서 폰트와 Worker를 불러옵니다.

공개 주소: https://jeonjinjeonjin.github.io/matter-type/

로컬 소스 변경 후 GitHub에 push해야 공개 사이트도 바뀝니다. 로컬 실행 창은 공개 사이트 운영에 필요하지 않습니다. 이미지 업로드는 브라우저 메모리에서만 처리되며 GitHub에 업로드되지 않습니다. 공개 저장소에는 소스가 공개됩니다. 배포본에는 테스트 페이지·개발 문서가 포함되지 않습니다.

외부 코드·폰트의 라이선스는 `public/licenses`에 함께 제공합니다. GitHub Pages 설정은 저장소 Settings → Pages → Source: GitHub Actions입니다.
